# יומן עברי — Smart Hebrew Calendar

מערכת חכמה לניהול **יומן עברי עצמאי** — יומן שבליבתו הלוח העברי (ולא רק שכבה מעל
לוח לועזי), עם **סנכרון דו-כיווני** ליומנים הנפוצים: Google Calendar,
Microsoft/Outlook, Apple/CalDAV, וקבצי ICS.

> פרויקט זה עצמאי לחלוטין ואינו קשור לקוד Rubeus שבשורש המאגר; הוא ממוקם תחת
> `hebrew-calendar/` בלבד.

## יכולות

- **לוח עברי מלא** — המרת תאריכים לועזי ↔ עברי (כולל שנים מעוברות, גימטריה),
  חגים ומועדים, פרשת השבוע, ראשי חודשים, וספירת העומר.
- **זמנים הלכתיים** — נץ, שקיעה, כניסת/צאת שבת, מולד — לפי מיקום גאוגרפי.
- **אירועים חוזרים עבריים** — יארצייט / יום הולדת / יום נישואין לפי התאריך
  העברי, עם חישוב המופע הבא (כללי אדר/אדר ב' בשנה מעוברת ול' חסר).
- **סנכרון** — יבוא/יצוא ICS, ו-Google / Microsoft / CalDAV דרך מתאמים אחידים,
  עם ניסיונות חוזרים והשהיה מדורגת, והתאוששות מסמן סנכרון שפג.
- **ארבע תצוגות** — חודש, שבוע, סדר-יום ושנה עברית, עם מגרת יום מפורטת.
- **מצב בהיר וכהה**, ממשק RTL מלא, ותמיכה מלאה במקלדת.
- **אירועי ערב** — היום העברי מתחיל בשקיעה, ולכן אירוע ב-21:00 משויך לתאריך העברי הנכון ולא לזה שהשעון מראה.
- **אזכרות ויארצייטים** — רשימה מרוכזת של שמות, המועד הבא לפי הלוח העברי, וזמן הדלקת הנר — עם תזכורות בהתראה, במייל ובאפליקציה.
- **מודעות מותאמות לציבור הדתי** — מלאי נמכר-ישירות (allowlist) ולא רשת פרסום פתוחה, ללא הצגה בשבת ובחג — או מנוי חודשי בעלות סמלית שמסיר אותן לגמרי.

## מבנה (monorepo, pnpm workspaces)

| חבילה | תיאור |
|-------|-------|
| `packages/core` | ליבת הלוח העברי (עוטפת [`@hebcal/core`](https://github.com/hebcal/hebcal-es6)) — ללא תלות ב-UI/רשת. |
| `packages/api`  | Backend: NestJS + Prisma + PostgreSQL. |
| `packages/sync` | מנוע סנכרון ומתאמים (ICS / Google / Microsoft / CalDAV). |
| `packages/web`  | Frontend: React + Vite (PWA, RTL עברית). |

TypeScript מקצה לקצה מאפשר בהמשך הוספת `packages/mobile` (React Native/Expo)
שמשתף את `packages/core`.

## התחלה מהירה (פיתוח)

```bash
cd hebrew-calendar
cp .env.example .env            # מלאו מפתחות OAuth לפי הצורך
pnpm install

# בסיס נתונים
docker compose up -d db
pnpm --filter @hcal/api prisma:migrate

# הרצה
pnpm dev:api                    # http://localhost:3001  (Swagger ב-/docs)
pnpm dev:web                    # http://localhost:5173
```

## בדיקות

```bash
pnpm -r test                    # כל בדיקות היחידה והאינטגרציה
pnpm --filter @hcal/core test   # ליבת הלוח העברי בלבד
pnpm --filter @hcal/web test:e2e  # בדיקות מקצה לקצה (Playwright)
```

בדיקות האינטגרציה של ה-API רצות מול PostgreSQL אמיתי, ולכן דורשות
`DATABASE_URL` ומסד נתונים פעיל (`docker compose up -d db`).
בסביבה שבה כבר מותקן Chromium אפשר להצביע עליו עם `CHROMIUM_PATH`.

הכול מורץ אוטומטית ב-GitHub Actions (`.github/workflows/hebrew-calendar.yml`)
בכל דחיפה שנוגעת ב-`hebrew-calendar/`.

## נגישות

הממשק נבנה לפי WCAG 2.1 ברמה AA ות״י 5568: ניגודיות הצבעים נאכפת בבדיקות
אוטומטיות, היומן נגיש במלואו מהמקלדת ומוכרז כטבלת ימים, וחלונות הדו-שיח
לכודי-פוקוס ומחזירים את הפוקוס בסגירה. הצהרת הנגישות זמינה בנתיב
`/accessibility`.

## מודעות

הפרסום נבנה סביב הדרישה שסוג המודעות ייבחר מראש ויתאים לציבור הדתי, ולכן
**ברירת המחדל היא מלאי נמכר-ישירות בלבד** (`AdCampaign` — רשימת היתר של מפרסמים
שאושרו), ולא רשת פרסום פתוחה שבה כל מודעה עלולה להופיע.

- **מודעות מעבר** (בין עמודים) נושאות מלאי עצמי **בלבד**. רשתות פרסום מחייבות
  שימוש בתגיות שלהן לפורמט הזה, ולכן עטיפת מודעת רשת בחלון משלנו הייתה מפרה את
  מדיניות המפרסמים — ולא הייתה מאפשרת לסנן את התוכן.
- **גיבוי רשת** (AdSense, אופציונלי דרך `ADSENSE_CLIENT_ID`) מוצג במשבצת
  שבתוך העמוד בלבד, וללא התאמה אישית כשהמשתמש לא נתן הסכמה.
- **קצב** מוגבל בצד הלקוח לפי `GET /api/ads/config`: לא בניווט הראשון, ולא
  יותר מ-`AD_INTERSTITIAL_MAX_PER_DAY` ביום. מודעה לעולם אינה נפתחת מעל
  חלון דו-שיח פתוח או מעל בקשת ההסכמה.
- **שבת וחג** — המודעות נכבות אוטומטית מהדלקת נרות ועד צאת הכוכבים, לפי
  המיקום של המשתמש ולפי לוח ארץ ישראל/חו״ל (`restWindowAt` ב-`@hcal/core`).
- **הסכמה** נגבית לפי תיקון 13 לחוק הגנת הפרטיות: אפשרות סירוב בולטת כמו
  האישור, בעברית, וניתנת לשינוי בכל עת ב״הגדרות״. אפשר גם לכבות מודעות לגמרי.
- נתוני ההגשה אינם כוללים מזהי משתמש: `/api/ads/*` אינו מאומת ואינו מקבל
  מזהה כלשהו.

## מנוי

כל יכולות היומן פתוחות לכולם. המנוי מסיר את הפרסומות בלבד — יומן שמסתיר זמנים
הלכתיים או אזכרות מאחורי תשלום הוא מוצר אחר, ופחות טוב.

שכבת החיוב ספק-אגנוסטית: `Subscription` + בדיקת זכאות אחת
(`BillingService.isAdFree`), ורק `paddle.adapter.ts` יודע על הספק. החלפת ספק
היא כתיבת מתאם נוסף, בלי לגעת בשאר. Paddle נבחר משום שהוא *merchant of record*
— הוא מטפל במע״מ ובחשבוניות, ולא נדרש רישיון סליקה.

הסרת הפרסומות נאכפת בצד הלקוח ולא בנקודות הקצה של המודעות, וזה מכוון:
`/api/ads/*` אינו מקבל מזהה משתמש, כדי שלא ניתן יהיה לקשר הצגת מודעה לאדם.
שמירת התכונה הזו שווה יותר מהפיכת הסרת הפרסומות לבלתי ניתנת לזיוף — במקרה
הגרוע מישהו יראה פחות מודעות ממה ששילם עבור הזכות לא לראות.

## הערת אבטחה

מפתחות OAuth וטוקנים אינם נשמרים במאגר. טוקני ספקים מוצפנים ב-DB באמצעות
`TOKEN_ENCRYPTION_KEY`. אין למסור סודות אמיתיים ב-`.env.example`.
